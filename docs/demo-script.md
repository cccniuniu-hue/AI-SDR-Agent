# 操作演示与讲解稿

[观看视频](assets/demo.mp4) · 5分12秒 · 中文合成语音。

视频为真实本地工作台六段操作录屏（约每秒采样一帧、输出10fps），剪去段间准备时间，后配Windows慧慧中文旁白；不是实时麦克风解说。全部通话为合成示例，模型和企业搜索为真实调用。

## 00:00–00:52 文本输入与架构

这是 AI SDR Agent 的本地操作演示。画面来自实际运行的应用，使用合成通话和真实 DeepSeek 接口，讲解采用合成语音。当前版本只接收文本，不上传音频，也不连接真实 CRM。应用以 Streamlit 展示页面，Python 工作流完成事实抽取、企业核实和意向评分，SQLite 保存结果与审核历史。这里输入一段客户明确说明痛点、试用时间、预算和演示要求的通话，并填写带时区的通话时间。点击分析后，系统已经核实企业主体并判为高意向。未提及的电话和门店数量保持空值，不能依靠常识补齐。

## 00:52–01:44 企业与意向证据

这一部分查看判断依据。企业识别先搜索公开来源，再要求模型提供候选全称及对应原文。程序重新核验引用、称呼关系、地区和行业；达到阈值且候选差距足够时才确认。这里的客户明确说了公司全称，酷家乐公司介绍提供了对应主体证据。品牌总部、加盟店或同名公司不能直接视为同一主体。下方意向评分分为痛点、时间、预算、推进意愿和使用规模五个维度。每个信号都保留客户原话。未知信号不按零分计算，机器质量分表示证据可靠程度，并不是客户购买的概率。

## 01:44–02:36 人工修正与确认

现在演示人工审核。审核人可以修改业务字段，未知项留空后仍保存为 null。这里根据原文补充具体的下一步行动，填写审核人和核实说明，再确认已经核查证据。点击预览只生成待保存的快照，数据库此时还没有改变。预览展示修改前后差异以及所依据的版本。确认保存后，系统记录审核事件，版本从一变为二。如果其他页面已经修改同一条记录，旧版本提交会被拒绝。人工审核不会抬高原始机器质量分，也不会覆盖首次机器结果，这样才能回溯每一次判断。

## 02:36–03:28 历史与明确拒绝

审核轨迹中可以查看操作者、时间、理由，以及完整的修改前后值。接着输入第二条合成通话。客户明确说不需要，目前没有采购需求，并要求不要再联系。真实模型分析后，系统判定为低意向，并保留拒绝原话。没有企业名称时，企业字段仍然为空，不能为了凑齐输出而猜一个主体。明确拒绝与信息不足需要分开处理。对于之前拒绝、后来明确要求采购的转折，抽取规则要求关注最新立场；如果证据矛盾无法解决，则保留未知并交给人工复核。

## 03:28–04:20 未知意向与JSON

第三条通话只有现在不方便、明天再说。这里没有足够证据判断采购意向，结果保持未知，而不是判为低意向。打开十五字段 JSON，可以看到企业、行业、联系人、电话、人数和意向等缺失信息都保留为 null。只有下一步建议提示补充信息，人工审核标记为真。导出的数据从数据库读取当前版本，字段类型由契约检查。电话号码保持字符串，人数只能是明确的非负整数。几十人、两三家或二十多人不能转成确定数量；销售介绍的能力，也不能自动成为客户事实。

## 04:20–05:12 批量审核与优化方向

最后展示批量审核。列表可以筛选线索并按稳定的记录编号选择。这里保留三条记录各自的字段，只统一完成审核，明确接受仍无法确认的空值，再预览整批结果。确认后使用一个事务保存，任意记录发生版本冲突时整批回滚。当前三条合成记录都已审核，可以导出 JSON。安装方式、设计说明、提示词和评测命令都在仓库中。后续重点是增加真实匿名业务样本，扩大企业正例与错字覆盖，校准阈值并评估审核成本。合成小样本成绩不能代表真实业务准确率。
