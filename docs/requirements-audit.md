## 与原题的明确口径

- 文本输入和本地复现均符合题目。无音频上传、无真实 CRM 是用户明确约定。
- 原题意向枚举只有 high/medium/low；用户已明确未知统一 null，因此信息不足时保留 null 并人工审核，不伪造低意向。
- 未明确的职位、时间、人数及无法核实的主体为 null。 approximate 人数原句在内部证据中保留，不能当作确定事实。
- 企业查询故障允许降级，但必须报告限制，不能把降级结果当成企业识别验收成功。
- 测试替身、合成数据、真实模型结果和真实业务数据评测分别标记，不能相互替代。

## 对实施计划的补充

1. 新增基础 Prompt 的直接输出基线，与完整工作流使用同一批标签进行对照；没有实测改进时如实报告。
2. 交付实际 5–10 分钟讲解视频。优先记录真实应用操作；如密钥、录制或旁白能力限制，明确列为未完成，不能以提纲替代。
3. 联调时先验证指定模型和搜索接口；若账号不支持配置的模型，使用 API 返回的可用模型并把实际配置、原因和兼容限制写入报告。
4. 最终交付状态逐项列出“已验证 / 有限制 / 未完成”，不因计划覆盖就宣称全部要求已满足。
