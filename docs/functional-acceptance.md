# 前端修改后的功能验收

验收日期：2026-10-19。依据：用户提供的四页《AI应用开发实习生笔试题目》，以及已确认的文本输入、DeepSeek、未知值统一 `null`、GitHub 仓库与本地运行说明、不接真实 CRM、不录视频。

结论：核心分析、证据查看、人工审核、批量订正、反馈和导出流程可用。本轮发现并修复 PDF 原例中联系人确认句的校验遗漏。企业简称的自动主体识别仍有覆盖限制，不能据此宣称全部企业识别准确。

PDF 原例的企业名称保持 `null`：搜索获得候选和来源，但没有足够证据确认通话客户的实际经营主体。页面明确提示人工核实，不能将保守留空计为企业识别成功。新简称、转写错字的自动还原仍需更多带真实企业标签的样本验证。

## 本轮发现与修复

原例中销售问“请问是张总吗”，客户紧接着回答“是的，你讲”。模型提供了这两段证据，但本地确认规则只接受“你说”“请讲”等表述，误将“张总”置空。

新增三条回归用例：接受“是的，你讲”；拒绝仅说“你讲”；拒绝确认后又否认身份。修复前一条失败、两条通过；补齐规则后全部通过。重启验收服务后再次真实分析，正确保留“张总”，不扩写姓名或推断职位。历史结果不被新规则自动改写。

## 浏览器与存储核对

- 单条审核：原例修改下一步行动并接受未知企业；预览时仍为 v1，确认后为 v2／已审核，保存审核人、说明和前后值。
- 批量企业与意向：两条测试记录按稳定编号从 v1 更新至 v2，再至 v3；意向改为 `medium`、审核状态为已审核，机器原值仍保留。合成企业名仅用于验证编辑功能。
- 批量导出：实际下载文件为两条对象数组，内容等于两条记录的当前 v3，每条 15 字段，`need_human_review=false`；未混入证据和审核元数据。
- 筛选：中意向筛选只显示对应记录；“中意向＋已审核”在审核前显示空结果提示；最近 7 天筛选正常显示本轮记录。
- 持久化与反馈：重新打开 SQLite，7 条分析、5 条审核事件、1 条测试别名及版本保持一致；查看和审核没有增加分析记录。
- 前端：本次美化已检查宽屏、中间宽度、窄屏、长企业名称、输入焦点和键盘切换；中间宽度下说明区域挤成竖排的问题已修复。
