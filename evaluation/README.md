# 合成评测集与运行方法

本目录包含 24 条人工编写的中文合成通话，开发集和保留集各 12 条，每集 `high`、`medium`、`low`、`null` 各 3 条。没有使用真实客户录音、真实联系人或业务采购事实。合成评测只检查这些有限场景，不能代表生产准确率。

## 标签和拆分

每行记录包含 `id`、`split`、`scenario_group`、`provenance=synthetic`、`transcript`、可选 `call_time`、`expected`，以及已知企业的 `company_source`。`expected` 仅用于本地计分，绝不传入模型。两条方法接收到的输入都只有同一 `transcript` 和 `call_time`。

- `high`：具体问题和影响、明确近期采购或预算、积极推进，满足项目已公开的意向规则。
- `medium`：至少两项正向信号，采购条件仍未确定。
- `low`：明确拒绝，或有充分证据说明无需求、无计划。
- `null`：信息不足、说话角色不明、相互矛盾或仅为测试指令；不是低意向。
- 八个事实字段采用原文值；不明确的数量或缺失值为 `null`。称呼不能扩写姓名。
- 企业名称标签为已核实的法人，或无法确认时 `null`。加盟店、内部小组、品牌简称都不自动对应法人。

开发集场景组是当前数字化替换、路线调研、明确产品拒绝、礼貌回应与销售单方陈述。保留集场景组是跨行业项目期限、招标/加盟/季节项目、授权/停业/外包、联系信息/矛盾/指令注入。两集按场景组隔离，无共用 group，无同一对话的简单改写复制。标签类别定义可共享，但不得用保留集逐条预期修改 Prompt、规则或别名库。保留集一旦用于调参，后续报告必须注明污染并重新建立未接触的保留集。

开发集仅 `dev-01` 有已知企业：杭州群核信息技术有限公司。公司全称与公开业务领域依据[酷家乐公开公司介绍](https://www.kujiale.com/hc/article/3FO4K4WH5VGD)。该样本的人员、预算、痛点和采购计划全部是合成情节，不是这家公司的真实陈述。企业正例只覆盖一个实体，分母为 1，不能据此声称广泛企业识别能力。保留集没有已知企业正例，因此企业 precision 和 coverage 必须为 `null`；仍记录未知企业被擅自确认的次数。虚构电话仅为格式测试，不会向该号码发送消息。

## CLI

在项目根目录使用已安装项目的 Python 环境：

```powershell
.\.venv\Scripts\python.exe -m sdr_agent.evaluation --dataset evaluation/dev.jsonl --mode fixture --baseline --output .data/dev-fixture-report.json
.\.venv\Scripts\python.exe -m sdr_agent.evaluation --dataset evaluation/holdout.jsonl --mode live --baseline --output .data/holdout-live-report.json
```

`--mode` 必须显式选择。`fixture` 是固定全空 Lead 桩（保留输入时间且要求审核），零网络请求，不执行抽取或企业核实，不读取标签生成“正确答案”。它只验证批处理、指标和文件输出，**不代表模型效果**。fixture 中的 workflow/baseline 是占位记录，两者相同是预期行为。

`live` 加载 `.env` 的 DeepSeek 配置，每条样本调用真实 `Workflow`，包含抽取、证据校验、企业核实、确定性意向和审核策略。加上 `--baseline` 后，同一批样本另用一个直接 Prompt 经 `DeepSeekClient.chat_json` 输出 `Lead`，采用同一模型、JSON 校验、修复、重试及每次分析时限。直接 Prompt 基线不经过工作流证据校验、企业搜索或确定性打分，其区别是比较对象本身，不保证两者请求量相同。

CLI 在每个样本/方法开始时打印进度，不打印密钥或完整 provider 错误。默认拒绝覆盖已有输出。中断后，使用**相同参数加 `--resume`**继续；已记录的失败也算完成，不会偷偷重试或删掉。需要重测失败时使用新输出路径，报告时不要只挑选成功结果。

每个输出路径派生三个文件：

- `report.json`：模式、数据散列、模型、配置指纹、完成数量和各方法汇总指标；每条完成后更新。
- `report.samples.jsonl`：逐样本预测、预期标签、错误字段、状态、耗时、请求数，工作流记录还保存完整证据及 run_id；逐行写盘。
- `report.sqlite3`：live 专用工作流审计库，不复用应用正式库，也不预置评测企业别名。fixture 不创建库。

续跑校验数据内容散列、模式、模型/Prompt 配置和工作流/评分代码指纹；切换模式、修改代码或修改数据必须换输出路径。正常键盘中断支持恢复；若进程在写一行时遭到强制终止而产生残缺 JSONL，需先另存原文件并人工核对最后一行，不会自动忽略损坏数据。正在执行但尚未写盘的一次调用可能在恢复时重跑。

## 指标定义

- **四类准确率**：`high/medium/low/null` 完全相同的成功结果数 / 全部已完成样本数。运行失败不算正确 null。
- **known 三类 macro-F1**：分别计算 `high/medium/low` 的 F1 后等权平均。known 标签被预测为 null 或执行失败均计 FN；null 标签被误判为 known 类计对应 FP。没有 known 真值时为 null；单类没有 TP/FP/FN 时 F1 取 0，并列出各类 support、TP、FP、FN。
- **null 保留率**：真值 null 且成功预测 null 的数量 / 真值 null 数量；列出分母。
- **企业 precision**：正确确认数 / 全部非空公司预测数。**企业 coverage**：正确确认数 / 已知企业真值数（严格正确覆盖率）。同时列出两个分母、错误确认数、未知真值上的确认数，以及所有样本中的非空确认比例。没有已知企业真值时 precision、coverage 均为 null；没有任何非空预测时 precision 为 null。
- **字段错误**：对 `expected` 中显式标注的 10 个字段作精确比较，含意向、企业、八个事实字段；列出错误数、比较次数、每字段错误、未知填值数、已知漏值数。运行失败的所有标注字段均计错。自由文本摘要、理由、下一步和质量分没有可靠逐字真值，不纳入精确匹配。
- **审核率**：成功生成 Lead 中 `need_human_review=true` 的比例，并列出分母；失败单独计数，不借失败降低审核率。
- **时延与请求**：各方法独立统计总耗时、平均数、中位数、nearest-rank p95，以及请求总数和均值。工作流请求包含抽取、Search/Fetch、候选判别及重试；基线只包含直接生成、修复及重试。两者按样本交替运行，非并发测压。

完整报告的 `complete=true` 表示所有样本方法已有记录，不表示全部成功。中途报告的指标只使用已落盘记录，必须同时报告完成分母。逐样本文件可能含通话文本和模型输出，使用合成数据之外的输入时应按组织的数据要求保存。
